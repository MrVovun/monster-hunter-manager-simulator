# Balance Reference

This document describes the current balance-critical systems and their formulas. Values below are the live values from `Assets/Resources/GameConfig.asset`, `Assets/Resources/GlobalHunterConfig.asset`, and `Assets/Resources/GlobalOrderDifficultyConfig.asset` unless noted otherwise.

## Referral System

Referral is handled by `OrderManager.ReferOrder`.

- The player must first declare a suspected monster.
- The order is removed from offered orders.
- The order state becomes `Failed`.
- The guild receives a case-quality payout.
- Referral advances action time through `GameConfig.actionTimeSettings.referOrderSeconds`.
- Referral income uses `GoldManager.AddGold`, so if the guild has debt, the referral payout pays debt before becoming spendable gold.

Current formula:

```text
ReferralFee = OrderReward * ReferralRate * CaseQuality * DailyReferralMultiplier
ReferralRate = GameConfig.referralRate
DailyReferralMultiplier = max(0.25, 1 - 0.20 * referralsToday)
```

`OrderReward` is the order's current gold reward. This includes dirty-floor reward penalties and trait reward scaling if they have already been applied to the offered order.

Default referral rate:

```text
ReferralRate = 0.25
```

Case quality:

```text
if declared monster family != true monster family:
    CaseQuality = 0
else if true monster has traits:
    CaseQuality = 0.40
                + 0.35 if declared monster is correct
                + 0.25 * revealedCorrectTraits / actualTraitCount
else:
    CaseQuality = 0.45
                + 0.55 if declared monster is correct
```

`referralsToday` resets at the start of each day. The first referral of a day pays 100% of the calculated value, then 80%, 60%, 40%, and 25% for the fifth and later referrals.

## Action Time

Time is action-based in `TimeManager`.

- Day states: `PreBell`, `Active`, `Evening`.
- `AdvanceTime(seconds)` only works during `Active`.
- In `PreBell`, the clock is visible but does not move.
- The first client bell starts the workday, then applies the bell's time cost.
- In `Evening`, normal actions no longer advance time.
- If an action pushes the day to zero remaining time, the day enters `Evening`.
- Active mission timers are reduced by action time. They do not reduce from real time.
- Mission timers receive the full action-time delta before the day-end clamp. Other `OnTimeAdvanced` listeners, such as hiring and Infirmary treatment, receive only the time that fit into the remaining workday.
- When the day enters `Evening`, all in-progress orders resolve immediately.

Current day length:

```text
dayLengthSeconds = 600
```

Current configured action costs:

```text
Ring client bell: 5
Accept order: 5
Refer order: 5
Send party: 5
Level up hunter: 5
Post hiring ad: 10
Review candidate profile: 5
Hire or decline candidate: 5
Build construction: 10
Choose kitchen recipe: 10
Clean kitchen plate: 3
Clean dormitory bed: 3
Clean stale dormitory bed: 6
Wash floor base: 5
Pass time step: 60
```

Dialogue question timing is mostly data-driven:

```text
client question time = InvestigationQuestion.askDurationSeconds + ClientProfile.responseDelaySeconds
hunter question time = InvestigationQuestion.askDurationSeconds
```

Floor washing is handled by `MainHallFloorDirtManager`:

```text
washTime = baseWashSeconds + dirtPoints * extraWashSecondsPerDirtPoint
```

If `useConfigBaseWashTime` is enabled, `baseWashSeconds` comes from `GameConfig.actionTimeSettings.washFloorSeconds`. The script default is `5`. The current `GameConfig.asset` should be opened and saved once in Unity so this newer field becomes visible in the asset.

## Order Generation And Mission Duration

Orders are generated by `OrderGenerator`.

Difficulty is selected from `DifficultyTable.entries` where:

```text
currentReputation >= entry.minReputation
currentReputation <= entry.maxReputation
```

Eligible difficulty entries are picked by dynamic weight:

```text
if entry.weight <= 0:
    effectiveWeight = 0
else if currentReputation > entry.minReputation:
    tierDelta = currentReputation - entry.minReputation
    effectiveWeight = entry.weight * max(minOldOrderMultiplier, lowerOrderDecay ^ tierDelta)
else if currentReputation == entry.minReputation:
    effectiveWeight = entry.weight * currentTierOrderMultiplier
else:
    effectiveWeight = entry.weight

entryChance = effectiveWeight / sum(eligibleEffectiveWeights)
```

Current dynamic order defaults:

```text
lowerOrderDecay = 0.45
minOldOrderMultiplier = 0.02
currentTierOrderMultiplier = 1
```

`currentTierOrderMultiplier = 1` means current-tier orders keep their normal weight.

Order values come directly from the selected difficulty entry:

```text
order.difficulty = entry.difficultyValue
order.missionDuration = entry.missionTimeSeconds
order.goldReward = entry.goldReward
order.xpReward = entry.xpReward
order.reputationPointsReward = entry.reputationPointsReward
order.reputationTier = entry.minReputation
```

After the investigation truth is rolled, monster traits scale gold and XP rewards once:

```text
traitRewardMultiplier = 1 + actualTraitCount * rewardBonusPerMonsterTrait
order.goldReward = round(order.goldReward * traitRewardMultiplier)
order.xpReward = round(order.xpReward * traitRewardMultiplier)
```

Current default:

```text
rewardBonusPerMonsterTrait = 0.33
```

This means each trait adds +33% reward. Three traits produce `1 + 0.33 * 3 = 1.99x`, effectively double reward.

There is also one reputation 0 entry with `weight = 0`. Important: `weight = 0` does not disable an eligible difficulty entry, because the picker clamps weights to at least 1. Monster selection:

- First filters monsters by required reputation.
- Then filters by minimum difficulty.
- If filtering removes every monster, the code falls back to the broader previous pool.
- Each monster has base `weight`.
- Preferred difficulty modifies its chance.

Monster difficulty multiplier:

```text
if orderDifficulty < monster.minimumDifficulty:
    multiplier = 0
else:
    distance = abs(orderDifficulty - monster.preferredDifficulty)
    normalizedDistance = distance / monster.difficultyFalloff
    curve = normalizedDistance ^ monster.difficultyFalloffPower
    multiplier = 1 / (1 + curve)

monsterPickWeight = monster.weight * multiplier
```

Final mission duration is calculated when the party is sent:

```text
finalMissionDuration = max(1, order.missionDuration * MissionOutcomeResult.MissionTimeMultiplier)
```

`MissionTimeMultiplier` is built from uncanceled monster traits, hunter trait mission effects, hunter bonus effects, and kitchen buffs:

```text
missionTimeMultiplier =
    monsterAndHunterMissionEffectMultipliers
    * clamp(1 - kitchenMissionTimeReductionPercent / 100, 0.01, 1)
    * hunterTraitMissionTimeMultipliers
```

## Success, Wounds, Death, And Rewards

Mission preview and resolution use `MissionOutcomeCalculator`.

Hunter progression stats come from the hunter's Level XP table, either directly on `HunterData` or inherited from a `HunterStatBlock`.

Each level row defines:

```text
level
requiredXP     // XP required to upgrade into this level
power          // hunter power at this level
upkeep         // daily upkeep at this level
levelUpCost    // gold required to upgrade into this level
```

Level 1 should usually have `requiredXP = 0` and `levelUpCost = 0`.

Base power formula:

```text
requiredPower = max(1, order.difficulty * requiredPowerMultiplier)
hunterPower = hunter.LevelXPTable[currentLevel].power
partyPower = sum(hunterPower) * partyPowerMultiplier
baseSuccess = clamp((partyPower / requiredPower) * 100, 0, 200)
```

Final success:

```text
successChance =
    clamp(baseSuccess + flatSuccessBonuses - debtSuccessPenalty, 0, 200)

successChance = clamp(successChance, 0, successCapFromTraits)
successChance = max(successChance, minSuccessFromTraits)
```

Important thresholds:

```text
successChance >= 100: mission success is guaranteed
successChance >= 150: success prevents wounds
successChance >= 200: success prevents death and can spawn a bonus chest
```

These are exposed on `GameConfig` as:

```text
successThresholdPercent = 100
woundProtectionThresholdPercent = 150
bonusRewardThresholdPercent = 200
```

Late dispatch:

```text
if party is sent while secondsRemainingInDay <= lateDispatchWindowSeconds:
    order.lateDispatch = true
    successChance -= lateDispatchSuccessPenaltyPercent
```

Defaults:

```text
lateDispatchWindowSeconds = 60
lateDispatchSuccessPenaltyPercent = 10
```

The order stores whether it was sent late. This matters because mission success is recalculated when the mission resolves, not only when the party is dispatched.

Current base risk values:

```text
baseInjuryChance = 0.5
baseDeathChance = 0.25
```

Final wound/death chance:

```text
injuryChance = clamp01(
    clamp01(baseInjuryChance after monster/hunter mission effects)
    * hunterInjuryChanceMultiplier
    * clamp01(1 - woundChanceReductionPercent / 100)
)

deathChance = clamp01(
    clamp01(baseDeathChance after monster/hunter mission effects)
    * hunterDeathChanceMultiplier
    * clamp01(1 - deathChanceReductionPercent / 100)
)
```

Mission resolver flow:

```text
success = successChance >= 100 OR random(0,100) < clamp(successChance,0,100)

if failed:
    traits with FailureRescueSuccessChancePercent can convert failure into success
    the rescuing hunter is forced wounded

for each hunter:
    if wounds are not prevented, roll wound chance
    if deaths are not prevented, roll death chance
    by default death requires the hunter to be wounded
    monster traits can allow death without injury
```

Lucky/reroll-negative logic:

```text
normalNegativeRoll = random(0,1) < chance
luckyNegativeRoll = max(random(0,1), random(0,1)) < chance
```

Rewards:

```text
successGold = round(order.goldReward * rewardMultiplier + rewardFlat)
failureGold = order.goldReward / 2
successXP = round(order.xpReward + additionalSuccessXP)
failureXP = order.xpReward / 2
if hunter died:
    successReputation = order.reputationPointsReward
else:
    successReputation = order.reputationPointsReward * (1 + trustStreak * trustReputationBonusPerStreak)
failureReputation = 0
```

Gold rewards use `GoldManager.AddGold`, so debt is paid first.

Guild Trust:

```text
clean success:
    if order.reputationTier >= currentReputation - trustEligibleTierBelowCurrentReputation:
        trustStreak += cleanSuccessTrustGain

messy success:
    trustStreak unchanged

failed order:
    if resetTrustOnFailedOrder:
        trustStreak = 0
    else:
        trustStreak = max(0, trustStreak - failedOrderTrustLoss)

hunter death:
    trustStreak = 0
```

Clean success means:

```text
mission succeeds
declared/suspected monster is the true monster
no hunter died
no hunter returned wounded
```

Referrals, declines, ignored orders, and canceled orders do not change Trust.

Current Guild Trust defaults:

```text
cleanSuccessTrustGain = 1
failedOrderTrustLoss = 2
resetTrustOnFailedOrder = true
trustReputationBonusPerStreak = 0.15
trustEligibleTierBelowCurrentReputation = 1
```

Bonus chest:

```text
if mission succeeds and successChance >= 200:
    spawn bonus chest
    mimicChance = 0.05
```

## Wounds And Healing

When a hunter is wounded, `HunterInteractionState.SetWounded(true)` marks them wounded. Dead hunters are set to `HunterState.Dead`.

Current healing routes:

- Overnight recovery at day start.
- Automatic Infirmary treatment if the Infirmary is built and treatment points are available.
- Legacy/manual healing code still exists, but it is not the current active balance path.

Overnight recovery:

- At new day start, wounded/healing hunters recover if `DormitoryManager.CanHunterRecoverOvernight` returns true.
- With no dormitory manager, recovery is allowed.
- With dormitory beds active, the hunter must have slept last night.
- Beds become dirty after use.
- Dirty bed cleaning time is `3`.
- Stale/unusable bed cleaning time is `6`.
- A hunter who did not sleep gets a flat missed-sleep success penalty.
- Current missed-sleep penalty script default: `10%`.

Infirmary:

- Requires the Infirmary construction to be built.
- Only idle wounded hunters are assigned.
- Hunters walk to treatment points.
- Treatment counts down from action time through `TimeManager.OnTimeAdvanced`.
- Current `InfirmaryManager.automaticHealDurationSeconds` script default: `10`.

## Bankruptcy And Debt

Upkeep is handled at day start in `GameManager.HandleDayStarted`.

Daily upkeep:

```text
dailyUpkeep = sum(active non-dead hunter.GetUpkeepCost())
```

Hunter upkeep:

```text
hunterBaseUpkeep = hunter.LevelXPTable[currentLevel].upkeep
hunterUpkeep = round(hunterBaseUpkeep * product(upkeepTraitMultipliers))
```

If upkeep is paid:

```text
unpaidUpkeepStreak = 0
debtSuccessPenalty = 0
```

Debt is paid by new income:

```text
when AddGold(amount):
    currentDayGrossIncome += amount
    debtPayment = min(debt, amount)
    debt -= debtPayment
    currentGold += amount - debtPayment
```

If upkeep cannot be fully paid:

```text
unpaidUpkeepStreak += 1
unpaidAmount = upkeepCost - currentGold
debt += unpaidAmount
spend all remaining currentGold
```

Day 1 unpaid:

```text
success penalty = 5%
reputation rank loss = 1
hiring campaigns still allowed
```

Day 2 consecutive unpaid:

```text
success penalty = 15%
reputation rank loss = 1
hiring campaigns blocked
hunters are dismissed until daily upkeep <= previous day's gross income
```

Current dismissal logic:

- Only non-dead, non-mission, non-candidate, non-armory hunters can be dismissed.
- The hunter with the highest upkeep is dismissed first.
- Dismissal stops once total upkeep fits yesterday's gross income or the minimum roster count is reached.
- Script default minimum roster count is `1`. If the asset has not serialized this newer field yet, Unity uses the script default.

Day 3 consecutive unpaid:

```text
game over
reason = "The guild failed to pay upkeep for three consecutive days."
```

Reputation rank thresholds are still stored in `GameConfig.orderLimitByReputation`, although order limits are no longer enforced:

```text
Reputation 1: 0 points
Reputation 2: 130 points
Reputation 3: 609 points
Reputation 4: 2058 points
Reputation 5: 10053 points
Reputation 6: 18477 points
```

## Hiring Campaigns

Hiring is handled by `HunterRecruitmentManager`.

Current global hiring config:

```text
basePostingFee = 10
costPerMinute = 20
arrivalIntervalSeconds = 10 to 20
maxCandidateQueueSize = 1
defaultInitialHunterCount = 1
rarity weights:
  Common = 0.5
  Uncommon = 0.25
  Rare = 0.125
  Mythic = 0.0625
  Heroic = 0.03125
```

Estimated campaign cost shown in UI:

```text
estimatedCost = basePostingFee + costPerMinute * (durationSeconds / 60)
```

Posting a campaign:

- Only allowed during `Active` workday.
- Blocked on Day 2 consecutive unpaid upkeep.
- Blocked if the hunter limit is reached.
- If another campaign is active, it is stopped and replaced.
- Existing candidates are cleared.
- The base posting fee is paid immediately, unless the campaign is tutorial/free.
- Posting advances action time by `10`.
- Campaign duration is at least `30` action-time seconds.

Active campaign spending:

```text
campaignTimeRemaining -= actionTimeAdvanced
burnAccumulator += (costPerMinute / 60) * actionTimeAdvanced
goldBurn = floor(burnAccumulator)
if SpendGold(goldBurn) succeeds:
    campaignCost += goldBurn
    burnAccumulator -= goldBurn
else:
    campaign stops for insufficient gold
```

Candidate arrival:

```text
nextArrivalTimer -= actionTimeAdvanced
when nextArrivalTimer <= 0:
    try generate candidate
    if success: nextArrivalTimer = random(arrivalIntervalMin, arrivalIntervalMax)
    if fail: nextArrivalTimer = 15
```

Candidate pool:

- Uses recruitable hunters available at current reputation.
- Excludes hunters already seen in the same campaign.
- Excludes already hired hunters through the hunter manager pool.
- Stops if candidate queue has reached `maxCandidateQueueSize`.

Candidate weight:

```text
rarityWeight = rarity.recruitmentWeight * activeRecruitmentRarityTraitMultiplier

if currentReputation > hunter.minReputation:
    rarityWeight *= lowerRecruitDecay ^ (currentReputation - hunter.minReputation)

powerScore = 1
if targetPower > 0:
    powerScore = clamp01(1 - abs(targetPower - hunterPower) / targetPower)

upkeepScore = 1
if maxUpkeep > 0:
    if hunterUpkeep <= maxUpkeep:
        upkeepScore = 1
    else:
        upkeepScore = clamp01(1 - (hunterUpkeep - maxUpkeep) / maxUpkeep)

traitScore = matchingPrioritizedTraitCount / prioritizedTraitCount

candidateWeight =
    max(0.01, 0.5
        + traitScore * traitPriorityWeight
        + powerScore * powerPriorityWeight
        + upkeepScore * upkeepPriorityWeight)
    * rarityWeight
```

Current scoring weights from script defaults:

```text
traitPriorityWeight = 2
powerPriorityWeight = 1
upkeepPriorityWeight = 1
lowerRecruitDecay = 0.55
```

Candidate interactions:

```text
review candidate profile: advances 5 action seconds
hire candidate: advances 5 action seconds
decline candidate: advances 5 action seconds
```

Hiring a candidate uses the normal hiring flow, so the candidate remains available in the pool if later fired. Firing saves their level, XP, and equipment state.
